# 第 5 章 导航（地图死了吗？）

> 这一波最容易让人误解的事，是以为 foundation model 替代了 SLAM（边建图边定位）。其实根本没换。它无非是在外面**包了一层语义皮**，让那张把空间切成格子、只标占没占的白茫茫占据栅格图，听得懂“去厨房”，仅此而已。底下那层做点云对齐的 ICP、回到老地方时把地图对齐的 loop closure、靠图优化把累积误差摊掉的 graph optimization，该跑的一个都没省。

---

先看一个典型的仓储盘点 setup。一台轮式底盘上的软硬件配置相当标准：车身前后各挂一颗 RealSense D455，顶上一颗竖直方向带 16 条扫描线的 Velodyne 16 线激光雷达，IMU（六轴：加速度 + 陀螺仪）选了 Bosch BMI088；算法上走 Cartographer 跑 2D LIDAR SLAM，再由 ROS2 时代的导航栈 Nav2 来做局部规划。

它在主货架区里走得稳稳当当。可一拐到货架尽头，停在那片用作打包区缓冲的金属反光支架前面，姿态估计就抖了起来。LIDAR 在那面金属上遭遇了回波多重反射，激光打出去再收回来，像平白走了一段不存在的距离。Cartographer 内部的 scan match score（当前帧能不能跟地图对齐的得分）开始报黄。视觉那边 ORB 特征点（一种角点检测 + 描述子）在反光金属上漂得更厉害，每帧抓到的角点跟上一帧根本不在一处。IMU 先跟着漏漂了大概十秒，姿态就直接拐到了墙里。

机器人当时接到的任务是去某个货位扫描箱子。在它错乱的内部坐标里，那个货位如今落在了墙体后面。它毫不犹豫地冲着墙走，撞上之后，costmap（代价地图：每格标走过去的代价）才把那一格涂成红色。重规划，绕开，再撞；一连撞了三次之后，全局重定位终于 trigger，总算把姿态拉了回来，前后生生丢了 40 秒。

到了 2026 年，这样的场景每天依然在工厂、仓库和医院里发生几千次。这并不是因为没人懂 SLAM，而是现实环境里总有 5% 的角落会让 SLAM 的假设当场崩掉。这一章要讲的，就是新一波 foundation 视觉特征与 VLN（视觉语言导航：照人话走）打算怎么去收拾这 5% 的残局，至于它们同样处理不了的另外几个 5%，到头来还得交还给经典老栈。

另一个对照同样常见。一台跑着纯视觉栈的家庭服务机器人，被部署在一栋老式公寓楼里。它在客厅里表现得近乎完美，问题偏偏出在连通客厅与卧室的那条走廊上：整条走廊长 4 米，两侧全无修饰的白墙，脚下的地板纹理整齐划一。导航栈跑的是基于 DINOv2 patch feature（每个图像小块的视觉向量）的 retrieval 定位（拿当前帧去库里找最像的，认为我就在那）。走到走廊正中间，它的 retrieval top-1 居然命中了训练数据里另一户人家的同款走廊，那张图像完全不属于这栋公寓。机器人却信心十足地照着那张图里的语境往前开，迎头撞上了一处训练数据里那户人家有、这户人家根本没有的门把手。

这件事在工程上被称作 hallucination，术语借自 LLM。“foundation 视觉特征在低纹理重复结构里会幻觉”成了 2024 - 2025 年家用机器人公司学到的最贵一课，几乎家家都掏过真金白银交这笔学费。

---

先把这套经典栈到底是什么交代清楚，并不是为了讲历史，而是因为后文的每一处讨论，都得频频回头拿它作对照。

**视觉 SLAM 这一线**。Mur-Artal 的 ORB-SLAM 系列（ORB-SLAM、ORB-SLAM2、ORB-SLAM3）在 2015 到 2020 年间，把 monocular（单目）、stereo（双目）、RGB-D（带深度的 RGB）与 inertial（带 IMU）全部打通。它的骨架很清晰：靠 ORB 特征点提特征，用 bag-of-words（把图像描成一袋视觉词）做 loop closure，再挂上 g2o（一个图优化求解库）做 graph optimization。这套体系至今仍是学术界的 baseline，也是很多消费级 AR 设备里跑的东西。同一时期，LSD-SLAM 和 DSO 走了 direct method（不挑特征点，直接用像素亮度对齐）的路子，特征点哪怕稀疏，稠密深度依然表现优异。

**LIDAR SLAM 这一线**。Google 的 Cartographer（Hess 等，2016）把 2D LIDAR + IMU 做到了仓库级别的稳定。3D 领域则沿着 LOAM 那一支演进，等到 LIO-SAM（Shan 等，2020）做出 IMU 紧耦合，连续几年都在 Hilti 比赛里斩获奖项。再往后，又涌现出 FAST-LIO2、Point-LIO 这类追求极致优化的版本。在工业部署场景中，LIDAR SLAM 这一支几乎是默认选择，因为它面对光照、纹理与动态变化，远比纯视觉抗造得多。

**融合**。各路传感器的分工向来明确：IMU 提供 short-term 高频姿态，wheel odometry 给出地面平移先验，GPS / RTK 充当户外的全局 anchor，LIDAR 与视觉则负责拉住长期的回环。底下的 EKF、UKF 或 factor graph 负责把这些信号死死焊在一块。Maybeck 那本 *Stochastic Models, Estimation, and Control* 固然是这一行的圣经，但在真刀真枪的工程现场，ROS 里那个现成的 robot_localization 软件包就足够用了。

**地图表示**。诞生于 1985 年的 occupancy grid（Moravec & Elfes，1985），至今仍是最常见的栅格地图。ROS 里的 costmap_2d 把静态层、障碍层和膨胀层一层层叠起来，让规划器拿到一张可以直接跑 A*/Dijkstra 寻路的地图。在 3D 空间里，OctoMap 稳坐了多年的头把交椅，直到最近，NeRF 与 Gaussian Splatting 这条技术线才开始挤进来，充当 dense 表示。

**规划栈**。ROS1 时代的事实标准是 MoveBase，到了 ROS2 则被全面重写为 Nav2（Macenski 等，2020 年起）。新架构把 behavior tree 放在顶层做调度，底层灵活接入各色 planner（NavFn、SmacPlanner）与 controller（DWB、TEB、MPPI）。走到 2026 年，绝大多数轮式平台部署的依然是 Nav2，没有任何一个 foundation model 真正替代了它。

先把这一段牢牢记住。后面聊起各种新东西时，每一处都要对照着这里问一句：“这件事究竟是真的替代了上面哪一行，还是只是往上叠了一层。”

---

新东西到底是什么。

**Foundation 视觉特征**。Meta 开源的 DINOv2（Oquab 等，Meta，2023）与后续演进，把 ViT 在大规模无标注图像上通过 self-supervised 训练得到的 patch feature 彻底公开。这类 feature 天生抗造，耐得住光照、视角与风格的变化，语义信息密度更是比 ResNet 那一代高出一个数量级。最直接的影响体现在两个地方：原先做视觉 place recognition 习惯用 NetVLAD 那一套，现在直接拿 DINOv2 patch feature 算个平均池化就能胜出；原先视觉里程计在低纹理白墙面前失效，如今 DINOv2 patch 面对白墙照样能顺利 match。另一边，SuperPoint + SuperGlue（Sarlin 等，2020）那一派同样在进化，LightGlue（2023）更是把推理速度直接拉到了实时水平。

**Open-vocabulary semantic mapping**。这是过去三年里最热的一条线。

- **CLIP-Fields**（Shafiullah、Pinto，2022）把 CLIP feature 烧进一个隐式神经场，让系统能用自然语言查询场景里的位置。输入“sink”这个词，出来的就是场景里水池所在的 3D 位置。
- **OpenScene**（Peng 等，CVPR 2023）把每个 3D 点的 feature 跟 CLIP 文本 embedding 逐一对齐，在 ScanNet 上做 zero-shot 3D 分割。
- **ConceptGraphs**（Gu 等，2024）迈得更远，把场景拆成 object node，每个 node 带上 CLIP feature 和文本描述，拓扑 graph 上直接跑 LLM query。像“找一个能装下我这只杯子的容器”这种问题，它能在 graph 上推算出来。
- **OK-Robot**（Liu 等，Meta + NYU，2024）把 ConceptGraphs 那一套接到了一台真机上，跑通了 pick-and-place 操作。这是第一个让人觉得“open-vocab 语义地图”在家里真的能用的工作。
- **HOV-SG**（Werby 等，2024）把分层场景图带了进来，自上而下分出区域、房间与物体三层，规划器可以在不同层做粗细不一的 query。

这一线里要点名的另一个是 **VLMaps**（Huang 等，2023）。这个工作把 CLIP feature 直接 project 到 2D top-down 地图上，让人在与 occupancy grid 同样的栅格里，就能直接查“沙发在哪”。它的工程直接，部署简单，到 2025 年很多公司内部地图都长成了这个样子。

需要看清的是，这些工作没有哪一个真正**替换了 SLAM**。它们全都是建立在已经由 SLAM 算出来的几何 backbone 之上，往上叠了一层语义。下层那一套 LIDAR + Cartographer + factor graph 没有任何变化。这件事，恰恰是这一波热潮中最容易被外人误解的地方。

还要再补一个最近的趋势：**Gaussian Splatting** 在 2024-2025 年挤进了导航这个圈子。3D Gaussian Splatting（Kerbl 等，SIGGRAPH 2023）原本是 graphics 里做新视角合成的工作，但它的副产品是一个稠密、可微、能实时渲染的 3D 表示。SplaTAM（Keetha 等，CVPR 2024）、Gaussian-SLAM 和 MonoGS 把 3DGS 跟 SLAM 焊在一起，让人边跑 SLAM 边建一张 photorealistic 的稠密地图。这件事在仿真闭环（拿真实 splat 当 sim 环境）与远程巡检（远端工程师戴 VR 头盔走进机器人扫出来的 splat 里看现场）上都开始有了产品。只是拿它充当定位 backbone 依然不够 robust，跑长了难免会漂，目前终究还是作为 dense layer，规规矩矩地叠在传统 SLAM 之上。

---

VLN 这一支则是另一回事。

Vision-Language Navigation 的 setup 是：人给一句自然语言指令（“走出这个房间，往左拐，进第二个有钢琴的房间”），机器人要按这句话从 A 走到 B。这个 task 在学术上对应着 R2R（Anderson 等，2018）、REVERIE（Qi 等，2020）、RxR（Ku 等，2020）、VLN-CE（Krantz 等，连续动作版，2020）这几个 benchmark。

跑 VLN 的环境主要有三个：

- **Habitat**（Savva 等，Facebook AI，2019 起到现在 Habitat 3.0）。在 3D 重建场景里运行逼真的 photorealistic agent。
- **Matterport3D**（Chang 等，2017）。扫了 90 个真实建筑，是绝大多数 VLN benchmark 的底层数据。
- **ScanNet**（Dai 等，2017）。包含 1500+ 室内场景的 RGB-D 扫描，重心更偏向 3D understanding。

学术界在 VLN 这条路上一做就是七年，真实部署直到 2025 年才开始有像样的工作。症结在于仿真器里的视觉 feature 跟真实 RGB 差得太远，这一侧的 sim2real gap，比机械臂抓取那边大得多。

真机部署这一路的转折点，来自 Sergey Levine 团队在伯克利做出的 **GNM → ViNT → NoMaD** 系列：

- **GNM**（General Navigation Model，Shah 等，2022）。在多个机器人平台、多个场景采集的 6000+ 小时数据上训练 goal-conditioned policy，输入当前图像与目标图像，输出 action。
- **ViNT**（Visual Navigation Transformer，2023）。把 backbone 换成 transformer，做到了基于 image-goal 的 zero-shot 跨平台泛化。
- **NoMaD**（Navigation with goal-Masked Diffusion，2024）。用 diffusion policy 把 exploration 与 goal-reaching 两个过程收进同一个网络里。

这一路方案的核心卖点，在于不需要度量地图（metric map）。给它一张目标图像，它就对着当前画面一步步走过去。网络内部维持着一种隐式拓扑，但绝不显式建图。

这里需要辨清界限：GNM、ViNT 和 NoMaD 并不是 **VLN**。它们接收的是图像目标而非语言目标。Levine 团队在这件事上格外坦率，他们认为图像目标比文本目标更稳健，因为画面直接抹平了语言里的歧义，省得机器人去猜“那个红色的椅子”到底指哪一把。真想把语言指令接进来，就得在外面再叠一层 VLM，把句子拆解翻译成阶段性的 sub-goal 图像；而这条路线（CoW、LM-Nav 这一线），直到 2025 年才开始出现像样的工作。

说到 VLN 的 sim2real 迁移，还有笔账需要算清楚。像 R2R 或 VLN-CE 这样的基准测试，在 Habitat 仿真器里跑出的成功率（SR，success rate）能到 60-70%，账面听起来很漂亮。可一旦拉到真机上，两年前能做到 20% 就算拔尖，眼下最好的工作也不过 40%。两边的差距并非模型不够强，而是 Habitat 渲染出的视觉特征与真实摄像头采到的 RGB 在色彩分布、模糊度和运动伪影上差得太远；在仿真里训练出来的策略，视觉那一端基本全要重训。这件事第 7 章会讲具体的解法。

---

讲到这里，该亮出第一个明确的态度了。

度量地图（metric map）与**拓扑地图**（topological map）的取舍，在传统机器人学界争论了三十年。度量地图给出精确坐标，拓扑地图只提供节点和边。Kuipers 早在 90 年代就用 Spatial Semantic Hierarchy 把分层架构讲透了，但在工业落地上，大家长期坚持跑度量地图，只因连续坐标更利于做精确规划。

进入 LLM 时代，拓扑地图之所以再度回潮，原因有三个。

第一，LLM 天然擅长在由节点与边构成的图上做符号推理，直接塞给它一套精确坐标系，模型反而无从下手。第二，基础模型的视觉 feature 让“两张图是否属于同一地点”的判断不再依赖精确几何匹配（geometric match），单靠特征距离就能判定，拓扑地图里的节点合并难题，头一回有了稳健的解法。第三，在长距离任务里，坐标误差的累积往往极其致命，而拓扑边只关注“能不能从 A 到 B”，对累积误差天生钝感。

像 ConceptGraphs 与 HOV-SG 这一路工作，本质上都在构建分层场景图（scene graph），也就是在拓扑地图的节点上挂载语义属性。走到 2026 年，技术走向愈发明确：底层的 metric SLAM 照旧在跑，但上层的规划，越来越多地交由拓扑与语义图来接管。

这本就是技术该走的方向，LLM 不过是把这个进程催熟了。

---

下面是这一章要立下的几个硬立场。

**立场一**：LIDAR 在户外和工业场景依然是默认选项，VLM 与基础视觉在户外充其量只能做辅助。

这条论断在 2026 年依然找不到反例。无论是 Waymo 的 robotaxi、Boston Dynamics 的 Spot，还是 Nuro 与 Agility Digit 在工厂部署的版本，全部跑着以 LIDAR 为核心的 SLAM 与定位栈。视觉模块只负责提取语义（行人、标牌、车道线），机器人的本体位姿（ego pose）绝不靠它。原因并不复杂：室外光照剧烈多变、测距跨度过大、动态物体杂乱，视觉的度量精度根本撑不住；而 LIDAR 给出 ±5 cm 的距离读数，是实打实的物理保证。

如果你接手的任务处于户外或半户外环境（园区、停车场、码头），第一选择依然必须是 LIDAR。为了压低成本，大可挑选固态 LIDAR（Livox、Hesai 的产品单价都已降到几千美金一颗），但千万别指望靠 4 颗 RGB 摄像头搭上 DINOv2 去替代它。那套方案能跑通 demo，却跑不通真实部署。

**立场二**：家用场景里纯视觉能接管 80%，剩下 20% 则会死在低光、重复走廊和玻璃墙上。

室内的情况刚好同户外反了过来。家庭环境的大部分区域属于强纹理、近距离、光照可控且动态干扰少，纯视觉技术栈能够跑得相当平稳。1X、Figure、Apptronik 这几家面向家用或商用室内场景的人形机器人企业，视觉方案在传感器配置中的比重一直在上升。Figure 的 Helix 公开 demo 里完全看不到 LIDAR；1X NEO 在家庭场景中，走的也是相机阵列方案。

但纯视觉方案在三个特定的家庭子场景里，始终绕不过去：

- **晚上灯关掉之后**。RGB 摄像头在 < 5 lux 下信噪比全线崩溃，DINOv2 那套特征也无济于事。面对这种环境，要么加上红外补光，要么加装一颗低成本 LIDAR，要么干脆提醒用户夜间不要让机器人巡逻。
- **重复走廊和重复墙面**。面对公寓楼里两条近乎相同的过道，纯视觉的地点识别（place recognition）很容易陷入混淆。这种地方要么引入 WiFi RSSI 或 UWB anchor 辅助判定，要么加一颗 LIDAR 靠空间几何结构来打破歧义。
- **大块玻璃墙**。摄像头直接穿透玻璃拍到后方的物体，算法便误以为道路通畅。这类场景 LIDAR 同样会失效，因为 905 nm 激光会直接穿透许多家用玻璃。目前最稳妥的工程解法，是在底盘前端加装超声波传感器或 ToF 相机，在近距离划出物理禁区。

从家庭环境部署中总结出的教训格外明确：硬件上至少要保留一颗超声波传感器或低线数 LIDAR 作为**兜底**。整机添置一颗 RPLIDAR A1 再配上几颗超声波，成本还不到 100 美金，但它能帮你省下的售后客诉，远不止这点账面支出。

再补一条一线工程摸索出来的经验：WiFi RSSI 指纹定位在公寓楼里其实比想象中好用得多。Google 自己的室内定位技术早在这套逻辑上跑了十几年。住户家里的路由器通常固定不挪窝，扫到的 BSSID 列表本身，就是一份极稳定的“人在哪个房间”的空间指纹。许多家用机器人厂商从不在宣传里大声声张，但悄悄把这层信息叠在视觉栈底下充当先验（prior），早已是行业内公开的秘密。它确实给不出厘米级的高精度，却能在视觉特征飘移时明确告诉你“机器人当下在客厅而非卧室”。单单加上这一层先验约束，全局重定位的搜索空间就能缩小一个数量级。

**立场三**：SLAM 并没有死，只是外面被包上了一层语义皮。

这是这一章最想彻底钉死的一句话。

市面上有些公司的营销话术常常宣称：“我们直接用 foundation model 做 navigation，不需要 SLAM。”出现这种论调，99% 的原因在于他们的仿真器里地面绝对平整、光照恒定如一，且完全避开了长期定位的需求。一旦把真机放到真实环境里跑上 30 分钟以上，跨过几个房间，碾过地毯与门槛，底座那套 SLAM 该怎么算依然得老老实实怎么算。

仔细翻阅 OK-Robot 的论文，其底层实际运行的依然是 ORB-SLAM3，作者在正文里写得清清楚楚。ConceptGraphs 在跑实验时，依赖的是预先扫描好的精细 mesh，而生成这张 mesh 的前置步骤本身就是 SLAM。VLMaps 同样立足于一个前提：必须先有一张度量地图充当底层 backbone。

新一波所谓的语义地图，无非是叠在传统 SLAM 之上的一层表征（representation）。LLM 与 VLM 进场之后，真正改变的只是给系统套上了一层交互 interface，让你得以用自然语言去 query 这张地图。但在地图底层，从 ICP、scan matching 到 loop closure、bundle adjustment 与 factor graph，经典的几何与优化算法一个都没少。

这件事情的要害，恰恰落在技术选型与团队招聘上。倘若真听信了“SLAM 已经过时”的论调，招来满屋子搞 VLM 的算法工程师，却找不出一个懂得调试 g2o 的人；等到真机部署在客户家中、连续运行半小时后位姿漂了整整 30 cm 时，整个团队将束手无策。在 2026 年的机器人行业里，能够沉下心调试修补 SLAM 系统的工程师，薪资身价远比只会调 VLM 的人昂贵得多。好好珍惜团队里仅有的那几位。

---

行人和动态障碍物，是导航领域另一个长期悬而未决的硬骨头。

围绕 **Social navigation** 的探索，从 Trautman 在 2010 年代初提出 IGP 起就一直在做。近些年涌现的 benchmark 包括 CrowdNav（Chen 等，2019）、SocialNav-SF（2022）与 SACSoN（2023）。发展到 NoMaD 这一脉，也开始在采集的数据集里主动加入行人。

走到 2026 年，这依旧是一个未解的 open problem。症结出在三个地方：

- 行人的行为意图是高度多模态的（要径直走过、要停下脚步、要主动让道，还是要走来搭话），机器人猜错意图的代价极不对称：碰擦到行人的代价，远比多绕两米远严重得多。
- 文化背景带来的差异极其悬殊。日本街头的行人往往会主动给机器人侧身让道，而纽约的行人可能就直接站在原地看机器人如何应对。单靠一份社交数据集，很难跨场景泛化。
- 评估指标始终难以达成共识。究竟何为“自然”几乎无法定量，规划轨迹究竟是否得体，往往只能凭 demo 视频的观感来评判，而非靠冰冷的数字指标。

在工业落地上，绝大多数团队目前的策略无非是选择**保守**：检测到 5 米内有人就降速至 0.3 m/s，距离缩短到 2 米内干脆停下让路，僵持超过 3 秒依然受阻便播放语音提示。这套逻辑谈不上优雅，但胜在安全可靠。未来两年内，这个难题大概率不会被 VLM 端到端一次性解决，而是要靠一份足够大的真实社交数据集配合行为克隆，一步一个脚印地落地。

顺手把一个常被忽略的关口说明白：**最后一米**。导航栈一路把机器人送到目标点周围 30-50 cm，这最后的临门一脚通常要交回给 visual servoing 或是 manipulation 那一侧的策略。这一段要是出了差错，跟前面整章讲的 SLAM 没什么关系，全是物体识别和精确定位的事。很多人算 navigation success rate 时不把这一米放进去，论文里写着 80% 的 SR，搬进实际产品能用的成功率常常一路跌到 50%，差出来的全在最后关头没能把物体认清楚。看 demo 的时候，眼睛要专门盯着这段。

---

把视线拉向户外看上一眼，正好拿来做个对照。

Boston Dynamics Spot 的导航栈完全是公开的：前后多颗双目摄像头管近处的 obstacle 避障，LIDAR 负责远距离 mapping，IMU 加上 leg odometry 结算姿态，graph nav 负责地点之间的 topological route。这套 graph nav 跟前面讲过的拓扑地图思路完全一致，但整个系统里**没有任何 LLM**。至于语义那一块，则是后来 Spot AI 团队往上叠出来的。

Waymo 那套系统自然不在本书的讨论范畴之内，但放出来对照仍有启发：它是工业界把 SLAM 做得最扎实的一家，走的是 HD map、LIDAR localization 配合多传感器融合的路子，定位上完全不依赖 foundation model。VLM 挤进这套系统，也只是用来做场景理解和异常检测的辅助帮手。这件事过去十年没有动摇，未来五年大概也变不了。

摆出这两个例子，无非是要说明一件事：表面上看大模型似乎已经全面接管，可工业界最严肃的一批玩家，底下依然稳稳保留着经典控制栈。家用机器人有充足的理由激进尝试，毕竟容错空间大，对硬件成本也极度敏感；可一旦来到户外或是自动驾驶，没人敢这么赌。

农业与野外巡检同样是一面镜子。Carbon Robotics、Naio 与 John Deere 这批跑在田埂间的农机设备，用的是 RTK GPS、LIDAR 加上视觉 row detection 的混合栈。RTK 在开阔田野里能直接给出厘米级的绝对定位，比任何 SLAM 都要精准。可一旦钻进树荫、温室或是楼宇夹缝，RTK 信号顷刻瓦解，系统必须毫无顿挫地切回 LIDAR 与视觉 SLAM。多源融合下的 health monitoring 机制，在工程上远比 SLAM 算法本身更难处理，工业部署里 80% 的 bug 都出在融合层，而非 SLAM 那一侧。刚入行的新手往往觉得 SLAM 才是最难啃的关卡，做过几年才明白，真正难啃的骨头全在后面。

---

写到最后，不妨把整章所有判断背后的 meta 立场彻底交代清楚。

这一轮导航浪潮里真正的质变，并不是 SLAM 已经消亡，而是**“什么是地图”**这件事情的边界被彻底拓宽了。

2018 年之前，所谓的地图不过是一张朴素的 occupancy grid。到了 2020 年，体系里加入了 OctoMap 与 NeRF 这类 dense 表示。2023 年，CLIP-Fields 与 ConceptGraphs 踏入赛场。而站在 2026 年回望，“地图”已经演变成一套复合架构：最底层的 metric grid 依旧坚挺，往上叠着一层由 Gaussian Splatting 构建的 dense 几何，几何之上架起包含场景拓扑的语义图（scene graph），而在最顶端，则留出一个供大语言模型检索调用的 text interface。

每一层架构各自应对一类 query：运动规划器去查 metric 坐标，VLM 去调取 dense 几何，LLM planner 在 scene graph 上做关系推理，最终用户则用自然语言检索 text。这四层结构并行不悖，谁也取代不了谁。

团队招人时，真正要找的是能在这四层架构里都说得上话的人。只守着最底层的工程师在 2026 年依然有饭吃，但个人的天花板已经被死死锁住；只懂最顶层的工程师能搭出漂亮的 demo，可系统一旦实机部署上线就会崩溃。夹在当中的那两层，才是眼下大多数公司最为紧缺的拼图。

千万别被论文标题里的“end-to-end navigation”给蒙住了。放眼真实世界，几乎没有一个做实际产品的导航栈会采用纯端到端方案。即便是 NoMaD 这样走得最激进的前沿探索，真正落地部署时，外层也必须老老实实包上一层避障 safety controller、一层 recovery behavior 加上一层 mission supervisor。把第 1 章那张端到端 vs 分层的判断表挪到导航场景下，90% 的 row 都会倒向分层。导航面对的物理现实恰恰跟抓取相反：耗时长、误差不断累积、失败代价高度不对称（撞人撞物比单纯走错路严重一个量级），几乎每一项特征都在把指针拨向分层体系。这也是为什么行业里最资深的那批老手，对“全端到端导航”的态度普遍十分冷淡。

## 练习

**重看一遍 OK-Robot 的 paper（Liu 等，2024）**。这次只读它的 hardware section 和 implementation details，跳过 method。数一数它底下到底跑了哪些“经典”组件，然后回到这一章问问自己：那些看似前沿的“新”工作，究竟有几个其实只是在老栈上面薄薄叠了一层？

**找一个你最熟悉的家庭/仓库机器人 demo video**。先按“户外 / 室内 / 半户外”给它打上场景标签，再去推测它选用了哪种定位栈（纯视觉 / LIDAR 主导 / 融合）。如果这家公司公开过技术博客，不妨找出来印证自己的判断。要是猜错了，回过头想想究竟是哪一步的直觉判断出了偏差？

**画一个你自己项目的“地图分层图”**。自底向上逐一梳理：底层 metric SLAM 选什么、要不要引入 dense 几何、scene graph 靠什么构建、最上层的 text query 又该如何接入 LLM。把每一层当前在团队里的负责人白纸黑字标出来。要是发现哪一层根本没人接手，或者大家异口同声说“这个我不懂”，那正是你下一个必须招人的岗位。

**找一段你公司或竞品 demo 里机器人在走廊或者家里跑的视频**。把视线移向背景里的玻璃门、镜面与长走廊，仔细观察机器人在路过这几处时是否出现过停顿、抖动或是不自然的绕行。在它卡顿挣扎的那几秒钟里，底层的控制栈其实正在毫无保留地告诉你：它究竟跑的是纯视觉，还是背后有 LIDAR 在默默兜底。
